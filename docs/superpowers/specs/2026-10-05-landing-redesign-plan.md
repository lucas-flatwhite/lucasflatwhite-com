## 1. 지금 무엇이 문제인가

- `/` 가 스네이크 게임 하나뿐이다. 처음 온 사람은 Lucas가 누구인지, 무엇을 만드는지, 어디로 가면 되는지 알 수 없다. 게임은 재미있지만 소개와 동떨어져 있다.
- `Hero`, `ProjectGrid`, `CommandShelf`, `FooterLinks` 컴포넌트와 프로젝트 콘텐츠(`src/content/projects`)는 남아 있지만 어디에서도 쓰이지 않는다.
- `global.css` 의 `body { overflow: hidden }` 이 사이트 전체에 걸려 있다. 게임 전용이어야 한다.
- 폰트 경로가 `/assets/fonts/...` 절대경로라 GitHub Pages 빌드(`base: /lucasflatwhite-com`)에서 깨진다.

## 2. 디자인 리드 (tasteskill 0.B)

> 개인 랜딩 + 링크 허브. 개발자/디자이너/한국 웹 커뮤니티가 대상. 실험적이고 키네틱한 타이포그래피 언어. 네이티브 CSS + canvas(pretext) + View Transitions 쪽으로 기운다.

## 4. 방향 후보

impeccable 방식대로 "이 사람만의 메커니즘"에서 출발했다. Lucas의 고유한 점은 **텍스트를 다룬다**는 것이다: 한국어와 영어 사이를 옮기고(gstack-ko, obsidian 번역), 웹에서 글자를 움직이게 만든다(pretext 기반 스네이크). 그래서 세 방향 모두 "글자가 재료"라는 공통점이 있고, 어떤 세계에 담느냐가 다르다.

### A. 활자 견본집 "Flatwhite Specimen" (추천)

Lucas 자체를 하나의 한/영 서체 견본집으로 보여준다. 이름, 소개, 링크가 모두 견본 페이지의 "글리프"가 된다.

- **첫 화면**: 화면 가득 한국어/영어 단어가 조판된 텍스트 필드(게임의 그 단어들). 그 위에 `Lucas Flatwhite` 와 `루카스 플랫화이트` 가 뷰포트 폭을 꽉 채우는 크기로 놓인다. 커서(모바일은 터치)가 움직이면 **본문 텍스트가 실시간으로 커서를 피해 다시 흘러간다**. pretext 의 줄 단위 레이아웃(`layoutNextLine`)으로 DOM 리플로 없이 60fps 로 돌린다. 이게 "증명"이다: 말로 "키네틱 타이포를 만든다"고 하지 않고, 첫 1초에 보여준다.
- **링크**: 견본집의 "글리프 표" 형식. 각 링크는 큰 아이콘 글리프 + 이름 + 한 줄 설명. 아이콘은 Phosphor 의 thin/regular/bold 굵기를 서체의 가변 굵기와 맞춰서, hover/focus 하면 글자와 아이콘이 함께 굵어진다. 그리고 아이콘마다 주제에 맞는 동사 모션을 하나씩 가진다 (5장).
- **색**: Drenched 전략. 한 가지 강한 색이 화면을 덮는다. 후보는 **울트라마린 바탕 + 우유거품 흰 글자 + 크레마 한 방울(산뜻한 노랑-주황) 액센트**. 커피 이름은 색의 이름에만 남기고 화면은 커피 색이 아니다.
- **서체**: 라틴은 폭(wdth)과 굵기(wght) 축을 가진 가변 그로테스크(후보: Anybody, Bricolage Grotesque), 한글은 가변 굵기 고딕(후보: Pretendard Variable 은 너무 흔하므로 SUIT Variable, Wanted Sans Variable 등 비교 후 결정). 실제 문구로 렌더링해 비교하고, 사용하는 글자만 서브셋해서 자체 호스팅.
- **위험**: 견본집은 쉽게 "신문 편집 디자인(헤어라인 + 이탤릭 세리프 + 작은 모노 라벨)"으로 미끄러진다. 헤어라인 장식과 작은 라벨을 금지하고, 거대한 글자와 꽉 찬 색면으로만 구성해서 막는다.

### B. 이중언어 사인 시스템 "Line Flatwhite"

서울 지하철 안내 사인처럼, 한국어 크게 / 영어 작게 쌍으로 된 안내판 체계. 링크는 "역", 카테고리(만들기/번역/놀이/연락)는 "노선 색"이 된다. hover 하면 그 노선이 켜지고 역 픽토그램이 그려진다. 주제별 아이콘 요구와 가장 자연스럽게 맞는다. 위험: 지하철 노선도 포트폴리오는 이미 꽤 있다. 키치해지지 않으려면 노선도 그림이 아니라 사인 시스템(타이포 + 픽토그램 + 색 규칙)만 가져와야 한다.

### C. 마이크로폼 "Microfoam"

이름을 글자 그대로 읽은 방향(후보 중 하나만 허용). 위에서 내려다본 컵 표면을 WebGL 유체로 만들고, 커서가 우유를 붓듯 단어들을 휘저어 라테아트 모양으로 `LUCAS` 를 그린다. 가장 화려하고 바로 "와" 소리가 나지만, 커피 키치와 크림/브라운 팔레트로 떨어질 위험이 가장 크고 성능 비용도 가장 높다.

**추천은 A.** 이미 있는 pretext 작업과 번역 작업을 그대로 증거로 쓰고, 게임과도 같은 세계(같은 단어 필드)를 공유해서 "동떨어짐" 문제를 정면으로 해결한다.

## 5. 링크 + 아이콘 시스템

링크는 텍스트 링크가 아니라 "살아있는 글리프"다.

- **라이브러리**: `@phosphor-icons/core` (SVG 원본, 런타임 0). 브랜드 로고(GitHub, X, Threads, LinkedIn, YouTube, Instagram 등)도 Phosphor 안에 있어서 한 패밀리로 통일된다. Phosphor 에 없는 브랜드(예: Obsidian)는 로고 대신 주제 아이콘을 쓴다.
- **데이터**: `src/data/links.ts`

```ts
type SiteLink = {
  id: string;
  label: string;        // "GitHub"
  labelKo?: string;     // "깃허브"
  blurb: string;        // 한 줄, 20단어 이하
  href: string;
  category: 'build' | 'words' | 'play' | 'talk';
  icon: PhosphorIconName;
  motion: GlyphMotion;  // 아래 표
};
```

- **아이콘별 동사 모션** (hover/focus 시 1회, `prefers-reduced-motion` 이면 굵기 변화만):

| 주제 | 아이콘 | 모션 |
|---|---|---|
| GitHub / 코드 | GithubLogo, GitBranch | 가지가 한 갈래 자라난다 |
| 번역 (gstack-ko, obsidian) | Translate | 글리프가 `가` 와 `A` 사이를 뒤집힌다 |
| 게임 | 스네이크 픽토그램 | 아이콘 안에서 뱀이 한 칸 움직이고 먹이를 먹는다 |
| X / Threads | XLogo, ThreadsLogo | 획이 그려지듯 나타난다 (stroke-dashoffset) |
| 메일 / 연락 | EnvelopeSimple | 봉투가 열리며 위로 살짝 뜬다 |
| 블로그 / 글 | Article, PenNib | 커서가 한 줄 타이핑한다 |

  모든 모션은 같은 이징(지수형 ease-out)과 같은 시간대(240~420ms)를 공유한다. 산발적인 hover 효과가 아니라 하나의 문법이다.
- **배치**: 같은 크기 카드 그리드 금지. 카테고리마다 다른 리듬으로, 큰 아이콘을 드롭캡처럼 쓰는 커다란 타이포 목록. 가장 중요한 링크 1~2개는 크게, 나머지는 촘촘하게.

## 6. 정보 구조

| 경로 | 내용 |
|---|---|
| `/` | 랜딩. 아래 섹션 구성 |
| `/play` | 스네이크 게임 (지금의 `/` 를 그대로 이전, 기능 변경 없음) |

랜딩 섹션 (같은 레이아웃 패밀리를 두 번 쓰지 않는다):

1. **첫 화면**: 텍스트 필드 + 이름 + 한 줄 소개(20단어 이하) + 주요 행동 1개. 스크롤 없이 링크 허브의 첫 줄이 화면 하단에 걸쳐 보이게 해서 "아래에 더 있다"를 문구 없이 전한다.
2. **링크 허브**: 5장의 글리프 목록.
3. **작업**: 프로젝트 3개. 카드 대신 가로로 넓은 견본 페이지. 각 프로젝트의 진짜 재료를 보여준다 (gstack-ko 는 실제 번역 전/후 문장, obsidian-translations 는 실제 문자열, 이 사이트는 게임 녹화 루프).
4. **놀이 밴드**: 화면 폭 전체의 게임 티저. 클릭하면 View Transition 으로 랜딩의 텍스트 필드가 그대로 게임 캔버스로 이어진다. 랜딩과 게임이 같은 세계라는 걸 전환 자체로 보여주는 서명 순간.
5. **마무리**: 연락 행동 1개(같은 의도의 버튼은 페이지 전체에 하나의 이름으로), 픽셀 컵 마크.

기존 자산 처리: 픽셀 flat white 컵은 메이커 마크로 유지. 게임의 단어 풀/버스트 문구는 랜딩 텍스트 필드에서 재사용. 쓰이지 않는 `Hero`, `ProjectGrid`, `CommandShelf`, `FooterLinks` 는 새 구조로 대체 후 삭제 (CommandShelf 의 `Ctrl/Cmd+K` 빠른 이동은 살릴지 질문 참고).

## 7. 기술 계획

- **스택 유지**: Astro 5 + TypeScript + vitest. 프레임워크 추가 없음. 새 의존성은 `@phosphor-icons/core` 하나 (서체 파일 별도).
- **공유 텍스트 필드 모듈**: `snake-experience.ts`(1642줄)에서 단어 생성, 레이아웃, 렌더 루프를 `src/lib/text-field/` 로 분리. 랜딩은 "장애물 피해 흐르기" 모드, 게임은 지금 모드. 같은 코드라서 View Transition 이음매가 자연스럽다.
- **성능**: canvas 는 화면에 보일 때만(IntersectionObserver), 탭이 숨으면 정지. DPR 상한 2. 이름/소개 텍스트는 캔버스가 아닌 실제 HTML 이라 LCP, SEO, 스크린리더가 안전하다. 캔버스는 `aria-hidden`. 한글 폰트는 사용 글자만 서브셋 (수 MB → 수십 KB 목표).
- **모션**: scroll 이벤트 리스너 금지. CSS scroll-driven animation(`animation-timeline: view()`) 우선, 미지원 브라우저는 그냥 보이는 상태. `prefers-reduced-motion` 이면 텍스트 필드는 정적 조판, 아이콘은 굵기 변화만.
- **브라우저 표면**: `::selection`, caret, 스크롤바, 포커스 링, 밑줄 offset 을 팔레트로 테마링.
- **버그 수정**: 폰트 경로를 base 경로에 맞게, `overflow: hidden` 을 `/play` 로 한정.
- **테스트**: 기존 소스 계약 테스트를 새 구조에 맞게 갱신하고 추가:
  - `links.ts`: 모든 링크가 https, 아이콘과 카테고리 보유, blurb 20단어 이하
  - 빌드 결과 HTML 에 `—` `–` 0개, 금지 폰트 이름 0개 (안티 슬롭 테스트)
  - `/play` 가 SnakeExperience 를 마운트하고 `/` 는 하지 않음
- **검증**: Playwright(사전 설치된 Chromium)로 1440px / 390px 스크린샷 1회 + 수정 후 확인 1회. reduced-motion 상태도 함께 캡처.

2. **링크**: 우선 GitHub, X 두 개. `src/data/links.ts` 에 항목을 추가하면 첫 화면(`featured`), 푸터, 커맨드 메뉴에 함께 나타난다.

## 10. 구현 메모 (계획과 달라진 점)

- **서체**: 라틴 Anybody Variable (wdth 50~150, wght 100~900), 한글 Noto Sans KR Variable. fontsource 로 설치해 Vite 가 base 경로까지 처리한다. 한글은 unicode-range 조각으로 쪼개져 화면에 쓰인 글자의 조각만 받는다.
- **이름 맞춤**: 가장 긴 줄(Flatwhite)을 78% 폭으로 기준 크기를 잡고, 짧은 줄(Lucas)은 폭 축을 늘려 양 끝을 맞춘다 (`src/lib/specimen.ts`).
- **텍스트 필드**: 게임 엔진(`snake-experience.ts`)을 쪼개는 대신, 같은 단어 풀과 pretext 를 쓰는 별도 모듈 `src/lib/text-field.ts` 를 만들었다. 게임과 랜딩은 장애물 처리 방식이 달라서 분리가 더 안전했다. 한글이 음절 사이에서 끊기지 않도록 pretext 를 0.0.9 로 올리고 `wordBreak: 'keep-all'` 을 쓴다.
- **첫 화면 링크**: 링크가 두 개뿐이라 별도 링크 허브 섹션 대신 첫 화면 오른쪽 아래에 둔다. X 는 로고가 곧 이름이라 라벨 대신 핸들을 보여준다 (`wordmark`).
- **작업 섹션**: 실제 저장소의 문자열 쌍을 사용했다. gstack-ko 는 upstream README 의 `/review` 설명과 한국어 README, obsidian-translations 는 `translations/ko.txt` 의 `setting.msg-restart-required`.
- **놀이 밴드**: 스스로 움직이는 뱀 주위로 단어가 비켜간다. Play 를 누르면 cross-document View Transition 으로 밴드 캔버스가 게임 화면으로 이어진다 (지원 브라우저만, 나머지는 일반 이동).
- **게임**: `/play` 로 이동, 동작 변경 없음. 상단 `/lucas-flatwhite` 가 랜딩으로 돌아가는 링크가 됐고, 커맨드 메뉴가 열려 있을 때는 게임 키 입력을 무시한다. 일시정지 문구의 em-dash 는 가운데점으로 교체.
- **검증**: `tests/anti-slop.test.ts` 가 em/en dash, 금지 서체, 그라디언트 텍스트, 글래스, 둥근 모서리, 아이콘 패밀리 혼용을 막는다.

## 11. 금속활자 구간 "Set by hand" (시안)

- **위치**: Work 와 Play 사이 (`#type`). 배경 3D 가 아니라 이 구간 하나에만 three.js 를 쓴다.
- **활자**: `scripts/build-type-sorts.py` 가 Anybody(wdth 100, wght 800)와 Noto Sans KR(wght 800)에서 이름 글자의 실제 윤곽을 뽑아 `src/data/type-sorts.json`(약 6KB)으로 저장한다. 각 활자는 금속 몸통 위에 거울상으로 돋을새김된 글자면을 가진다. 활자 높이는 크기와 상관없이 같고(type-high), 띄어쓰기 자리에는 낮은 공목(spacer)이 들어간다.
- **상호작용**: 커서나 손가락으로 밀면 활자가 밀려나 돌았다가 스프링처럼 제자리로 돌아온다. 서로 겹치지 않는다.
- **교정쇄**: 버튼을 누르면 크레마색 롤러가 지나가며 활자면에 잉크를 바르고, 종이가 내려와 눌린 뒤 들어 올려져 돌아선다. 종이에 찍힌 내용은 그 순간 활자가 놓인 위치와 회전을 그대로 반영한다 (밀어 둔 활자는 밀린 채로 찍힌다). 다시 누르면 활자를 정리(distribute)한다.
- **비용**: three.js 청크는 gzip 약 150KB. 구간이 화면 600px 앞에 왔을 때만 불러오고, WebGL 이 없으면 불러오지 않는다. 움직임이 없으면 렌더링을 멈추고, 화면 밖이나 숨은 탭에서도 멈춘다.
- **대체 화면**: three.js 가 뜨기 전이나 WebGL 이 없을 때는 같은 자리에 이름이 텍스트로 보인다. '동작 줄이기' 설정에서는 교정쇄 과정이 애니메이션 없이 결과로 바로 넘어간다.

## 12. 프로필 이미지 (2026-10-19)

- **상단 바**: X 프로필 이미지(`public/avatar.png`, 96px)를 핸들 왼쪽에 32px(모바일 28px) 원형으로 둔다. X 에서 보던 얼굴이라는 신호로만 쓰고, 이름과 시선을 다투지 않도록 크게 쓰지 않는다. 사이트에서 유일하게 둥근 모양이며, `tests/anti-slop.test.ts` 의 각진 모서리 규칙은 `.topbar-avatar` 하나만 예외로 둔다.
- **공유 이미지**: 같은 이미지(`public/og-image.png`, 600px 정사각형)를 `og:image` 와 `twitter:image` 로 지정한다. `twitter:card` 는 `summary` 라서 링크 카드에 정사각형으로 뜬다.
- **좁은 창**: 아바타가 들어가면 상단 바에 여유가 거의 없다. Chromium 에서 재 보면 340px 미만에서는 그냥 둬도, 401px 미만에서는 핸들에 마우스를 올려 글자가 넓어지면 오른쪽 여백을 넘는다. 그래서 420px 미만에서는 핸들이 색만 바뀌고 넓어지지 않으며, 360px 미만에서는 ⌘K 버튼을 숨긴다. 단축키는 그대로 동작하고 푸터가 안내한다.

## 13. 모바일 다듬기 (2026-10-20)

- **스크롤할 때 깜빡임**: 첫 화면이 `100dvh` 라서 휴대폰 툴바가 접히고 펴질 때마다 높이가 바뀌었고, 그때마다 캔버스 크기가 다시 잡히며 한 프레임 비었다가(크기를 바꾸면 캔버스가 지워지는데 다음 프레임에야 다시 그렸다) 단어 전체가 새로 흘렀다. 첫 화면을 `100svh` 로 고정하고, 크기가 바뀐 그 프레임 안에서 바로 다시 그린다. 스크롤하려고 화면에 댄 손가락을 렌즈가 쫓아갔다 돌아오던 것도 막았다. 렌즈는 마우스와 펜만 따라간다.
- **줄 고정**: 텍스트 필드는 한 줄로 이어진 글이라, 렌즈가 한 줄을 건드리면 그 아래 모든 줄이 매 프레임 다시 흘렀다. 한 줄에 단어가 여덟 개 남짓인 휴대폰에서는 이게 링크 옆 작은 글자들까지 깜빡이는 것으로 보였다. 720px 이하에서는 각 줄이 시작 단어를 기억해서(`TextField.anchor`) 렌즈가 지나가는 줄만 움직인다. 렌즈 옆에 들어가지 않는 단어(예: `Martin\u00A0Garrix`)는 건너뛰고 다음 단어를 채우되, 다음 줄이 시작하는 단어 앞에서 멈춰 같은 단어가 두 번 보이지 않는다.
- **렌즈가 원으로 보이게**: 휴대폰에서는 이름이 첫 화면 대부분을 차지해서, 단어가 놓일 자리는 상단 바와 이름 사이 대여섯 줄뿐이다. 렌즈는 화면 전체를 떠다니며 대부분 이름 뒤에 숨어 있었다. 이제 그 띠(`TextField.openBand`)에 맞춰 반지름을 줄이고 띠 안에서만 떠다니며, 가장자리를 1.5px 크레마 선으로 그린다. 글자만으로는 몇 줄짜리 띠에서 원의 윤곽이 서지 않기 때문이다. 상단 바의 아바타에 이어 두 번째 원이지만 캔버스 위의 움직이는 렌즈라서 각진 모서리 규칙과 부딪히지 않는다. 띠가 너무 낮은 화면(예: 375×553)에서는 렌즈 없이 단어가 가만히 있는다. 데스크톱은 그대로다.
- **링크 이름**: GitHub 은 서비스 이름, X 는 핸들, 이메일은 주소를 보여줘서 셋의 결이 달랐고, 첫 화면에 `lucas flatwhite` 가 다섯 번 나왔다. 셋 다 서비스 이름(GitHub, Twitter, Email)으로 통일하고 `wordmark` 를 없앴다. X 는 로고는 그대로 두고 이름을 Twitter 로 부른다. 주소는 푸터의 Email 설명에 한 번만 적는다. 클릭하면 여전히 주소가 복사되고 이름이 Copied 로 넘어간다.
- **Kent Beck**: 무대 위의 `Kent Beck` 표기를 뺐다. 인용의 출처는 구간 소개 문장("Kent Beck's three steps")에 남는다.
- **⌘K 버튼**: 터치 기기(`hover: none`, `pointer: coarse`)에서는 일부러 숨긴다. 키보드 단축키를 알려주는 버튼이고, 열면 입력창에 커서가 가서 화상 키보드가 올라온다. 휴대폰에서는 상단 바의 Work, Play 와 첫 화면 링크가 같은 역할을 한다.

## 14. 첫 화면 링크 정렬 (2026-10-20)

- **무엇이 어긋났나**: 데스크톱에서 GitHub, Twitter, Email 은 오른쪽 여백에 붙어 오른쪽 정렬인데 아이콘이 글자 앞에 있어서, 글자 길이에 따라 아이콘이 최대 36px 들쭉날쭉했다. Email 의 CopyRoll 은 보이지 않는 "Copied" 폭만큼 넓어서 오른쪽 끝도 안쪽으로 밀렸고, 줄 높이 1.2 때문에 Email 줄만 12px 높아 간격이 고르지 않았다. 휴대폰은 왼쪽 정렬이라 앞의 두 가지가 보이지 않았다.
- **바꾼 것**: 720px 보다 넓으면 아이콘이 글자 뒤, 오른쪽 여백에 한 줄로 선다. 아이콘을 앞에 둔 채 왼쪽 정렬하면 hover 로 글자가 넓어질 때 나머지 줄까지 밀리기 때문이다. 이제 hover 한 줄만 왼쪽으로 넓어진다. Email 의 글자는 CopyRoll 의 끝에 붙고, 세 줄 모두 CopyRoll 과 같은 1.2 줄 높이를 쓴다. 휴대폰은 아이콘이 앞에 오는 지금 배치 그대로이고 줄 간격만 고르게 됐다.
- **확인**: 1024, 1280, 1440, 1920px 에서 세 아이콘의 오른쪽 끝, 줄 높이, 아이콘과 글자 사이가 모두 같고, 어느 줄을 hover 해도 다른 줄의 아이콘은 움직이지 않는다.

## 15. Work 그림 (2026-10-20)

- **왜**: Work 의 두 항목은 각 프로젝트에서 뽑은 한국어 문장 한 줄("ChatGPT 공개", "백남준은 TV로 그림을 그렸고")을 증거로 크게 보여 줬는데, 그 문장만으로는 프로젝트가 무엇인지 와닿지 않았다. 그 자리를 프로젝트마다 하나씩 만든 정지 그림이 대신한다.
- **AI Timeline Log**: 그 프로젝트의 목판 엔진(`scripts/work-art/engrave.js` 로 옮겨 옴)으로 새긴 입력창 판. 커서가 선 입력창에서 동심원 결이 퍼지고, 짙은 파랑 바탕에 흰 선이다.
- **lucasflatwhite.com**: 고흐의 1889년 자화상처럼 파란 소용돌이 속에 앉은 고양이를 붓질 대신 단어로 칠한 자화상. 단어마다 Anybody 의 굵기와 폭이 붓을 누르듯 커졌다 줄어들고, 고양이 몸에는 lucas, 루카스 같은 단어가 섞여 있다.
- **형식**: 둘 다 `npm run art` 가 미리 만들어 커밋한 SVG(`src/assets/work/`)이고 `<img loading="lazy">` 로 뜬다. 자화상은 쓴 글자만 남긴 Anybody 와 Noto Sans KR 을 안에 품고 있어서 `<img>` 안에서도 사이트 서체로 그려진다. gzip 기준 목판 약 30KB, 자화상 약 57KB. 애니메이션은 없고, 발췌 제목의 스크롤 효과도 함께 뺐다.
- **자세히**: `docs/superpowers/specs/2026-10-20-work-art-design.md`.

## 16. 첫 화면의 Work 링크 (2026-10-25)

- **왜**: 프로젝트 링크는 스크롤을 내려 Work 에 가야 보였고, 첫 화면에는 상단 바의 Work 한 단어뿐이었다.
- **바꾼 것**: 소개 문장 아래에 `Work · AI Timeline Log ↗ · lucasflatwhite.com ↗` 를 한 줄로 둔다. Work 섹션과 같은 `work` 목록을 읽고, Work 항목처럼 각 프로젝트의 `href` 를 새 탭에서 연다(lucasflatwhite.com 은 GitHub 저장소). 링크마다 `data-field-obstacle="hero"` 를 달아 단어 들판이 비켜 흐른다. 시안은 html-plan 으로 오른쪽 칸, 작은 그림 카드와 견주어 골랐다.
- **hover**: 색만 크레마로 바뀌고 넓어지지 않는다. 넓어지면 옆 링크가 밀려 단어 위에 겹쳤다. 단어 들판은 크기가 바뀔 때만 장애물을 다시 재기 때문이다.
- **휴대폰**: "Work" 제목은 스크린리더만 읽고 화면에는 감춘다. 보이면 두 링크가 둘째 줄로 꺾여 이름 위 단어 자리를 한 줄 더 차지한다. 360px 폭에서는 제목 없이도 두 줄이 된다.
- **⌘K**: Work 다음, Play 앞에 프로젝트가 하나씩 들어간다. 힌트는 태그라서 "canvas" 로도 찾는다. `/play` 의 메뉴도 같다.
